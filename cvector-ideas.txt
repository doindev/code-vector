I want to create a java application, this simplistic idea behind this application is it will have these capabilities:
1) it will primarily use a neo4j database
2) it will thoroughly examine each and every file in a project and add records in the graph database mapping all relations of each file to the other so we could ask it questions like if i change this table schema what happens? and the response will give me the full file path and the line number in the file that will be affected so I know exactly what could break.
3) it will monitor specific project directories as identified by the user for file changes and add/remove/update graph's as the files change.
4) file monitoring can be live or cron'd to check periodically defined by user input
5) the initial parser will support: maven, java, spring, SQL, Javascript, Typescript, YAML, JSON configs. And then at some point I would like to add support for Python, Terraform, Dockerfile, C#, Rust, Go, .env.
6) Parsers will extract details on code, API, data, infrastructure, config, security issues.
7) The application will enable API access for programmatic interaction.
8) These same API's will be exposed as MCP Tools
9) This application will also support CLI commands for the same API'same

example CLI commands:

# This will initialize a new project with the path being the current directory
cvector init

# This will parse all suported file and ingest nodes and edges into neo4j
cvector scan <path>

# This will scan a specific directory and give it a specific project name
cvector scan ./src --project my-api

# This will perform a git diff-based selective re-scan, only files changed since the last commit are re-parsed
cvector scan:incremental .

# This will provide continous file monitoring with real-time reindex and impact warnings
cvector watch .

# This will check the neo4j connection and display project statistics
cvector status

# This will provide full diagnostics of the cvector setup
cvector doctor

# This will execute a raw Cypher query against the graph
cvector query "cypher"

# This will display the most recently modified nodes, 2 examples
cvector recent
cvector recent --since 24h --limit 10

# This will display downstream impact analysis - find everything that might break if a symbol changes, 2 examples the 2nd has depth control
cvector impact <symbol>
cvector impact <symbol> --depth 5

# This will provide full context for a symbol - callers, callees, file location, edges.
cvector explain <symbol>

# This will analyze the blast radius of changes in the current branch with 2 examples the 2nd outputting the results to a file
cvector pr-impact
cvector pr-impact > impact.json

# This will find all the files that should be re-run after a change
cvector test-impact <symbol>

# This will perform a graph-aware rename showing all the affected files
cvector rename <old> <new>

# This will provide guided migration plan with risk assessment
cvector migrate <symbol>
cvector migrate <sybmol> --to <new-file-path-and-name>

# This will display architecture drift between two scans
cvector diff <sha1> <sha2>

# This will show the cross-service dependencies through queues, events, and APIs, etc...
cvector service-links

# This will evaluate architecture rules
cvector rules

# This will initialize the rules config
cvector rules --init

# This will perform a quality gate for CI and pre-commit
cvector guard							# interactive output with colors
cvector guard --ci						# CI mode (exit code 1 on failure)
cvector guard --json					# JSON output for automation
cvector guard --god-file-threshold 20	# Custom threshold (default: 15)
cvector guard --install-hook			# Install as git pre-commit hook
cvector guard --uninstall-hook			# Remove the pre-commit hook

# This will display dependency vulnerabilty check with graph blast radius
cvector audit

# This will run everything in one command: scanning, rules evaluation, quality gate, dependency audit
cvector ci

# This will skip the scan if graph is up to date
cvector ci --skip-scan

# This will provide a one-command codebase briefing based on the application in the current directory
cvector onboard

# This will generate a markdown documentation from the graph
cvector wiki --out ./wiki

# This will auto-generate a changelog from graph changes
cvector changelog --since 7d

# This will generate health badges for your README.md
cvector badge

# This will detect functional clusters using union-find algorithm
cvector communities

# This will trace execution flows from entry points through the call graph
cvector flows

# project management - multiple projects in a single neo4j database via projectId isolation
cvector project list				# list details of each project, file count, node count, ...

config is stored in .cvector/project.json. All nodes carry a projectId - queries automatically filter by the active project.





# MCP Tool calls
## Search and exploration
cv_search				# search nodes by name with wildcard support, key-parameters[query,limit]
cv_context				# full context for a file or function, ... - what it contains, calls, is called by, imports, ... , key-parameters[name]
cv_explain				# deep-dive into a symbol: type, file, location, all callers, all callees, edge counts. key-parameters[symbol]
cv_projects				# list all tracked projects with IDs and metadata

## Impact Analysis
cv_impact				# downstream impasct analysis, find everything that breaks is a symbol changes, key-parameters[symbolId,depth,minConfidence]
cv_trace				# shortest dependency chain between two symbols(names only), key-parameters[from,to]
cv_path					# deteiled path between two symbols with node types and relationship types at each step, key-parameters[from,to]
cv_db_impact			# database table/column read-write analysis, find all functions that read from or write to a table, key-parameters[table,column]
cv_test_impact			# find all test files affected by changing a symbol or file, key-parameters[symbol or files]
cv_rename				# graph-aware rename impact, shows definition, all callers, importers, and affected files. key-parameters[symbol]

## Architecture and Quality
cv_health				# codebase health metrics with optional dead code, god files, god objects, and duplicate analysis. key-parameters[includeDeadCode,includeGodFiles,includeDuplicates]
cv_communities			# detect functional clusters, groups of code that frequently call each other. key-parameters[minSize]
cv_flows				# trace execution flows from entry points (routes, event, listeners, queue consumers, ...) through a call graph. key-parameters[maxDepth,limit]
cv_rules				# evaluate 9 configurable architecture rules plus custom Cypher rules. key-parameters[threshold parameters]
cv_guard				# quality gate check, returns pass/fail per rule with violations. key-parameters[threshold parameters]
cv_diff					# architecture drift between two git SHAs, new/removed files, functions, and call edges. key-parameters[fromSha,toSha]
cv_service_links		# cross-service dependencies through message queues, event buses, and API calls. 	

## Reporting
cv_changes				# recently modified nodes with types and file paths. key-parameters[since,limit]	
cv_onboard				# full codebase briefing, stats, language distribution, DB tables, external APIs, env vars, high-risk functions.
cv_wiki					# structured documentation data, file index, top functions, health report, cross-service links. key-parameters[section,limit]
cv_audit				# dependency vulnerabilty check cross-referenced with the knowledge graph to show blast radius.	


# Resources - browsable read only data endpoints that AI assistants can access directly. All resources are project-scoped via projectId.

/communities	# functional clusters with cohesion scores
/onboard		# full codebase briefing
/schema			# all node labels and relationship types with counts
/projects		# all tracked projects
/infrastructure	# queues, metrics, spans, topics, crons, events, APIs, env vars
/guard			# quality gate status
